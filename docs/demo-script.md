# 演示剧本：政务档案场景，右侧 Agent 手动上传走完三大功能

> 一句话立场：**AI 负责读、找、对、写初稿；人负责确认、定界、承诺。**
> 右侧是交互面，中间是产物面 —— 不管中间切到哪一页，右边都是同一张状态卡和同一段对话。

## 场景设定（两套数据分开）

| 谁 | 是什么 | 从哪来 |
| --- | --- | --- |
| 星云科技（我们公司） | 7 个产品 / 9 份能力文档 / 5 个历史案例（含政务信创案例） | 预置在企业知识库里，演示中不变 |
| XX市档案馆（客户） | 两份客户材料：招标需求书（3 页）+ 招标答疑与补充通知（2 页） | `demo/` 目录，演示时你手动上传 |

两份材料是配套设计的，制造两个演示点：

1. **工期口径冲突**：需求书写 4 个月，答疑改成 3 个月 —— 项目要点会按原文各记一条，人一眼看到矛盾；
2. **特殊档案类型**：需求书只说"5 类特殊档案"，答疑才给出清单（多页 OFD、无边框台账、手写批注、繁体历史档案、大幅面图纸）—— 演示"新信息让待确认项变具体"。

## 0. 准备（开演前 2 分钟）

```bash
# 生成两份客户材料（只需一次；改了内容再跑）
.venv\Scripts\python.exe scripts\make_demo_materials.py

# 清场 + 建一个空白演示项目（会先备份数据库）
.venv\Scripts\python.exe scripts\demo_reset.py --purge
```

它会打印演示入口链接，并把项目停在**材料 0 份、需求 0 条**的干净起点。

想自己先跑一遍流程，用预演模式（需要后端已在跑）：

```bash
.venv\Scripts\python.exe scripts\demo_reset.py --purge --preload
```

想把整条链（材料 → 需求 → 判断 → 建议 + Agent 批准卡）自己先走一遍、并看到每步的数字，用演练脚本：

```bash
.venv\Scripts\python.exe scripts\demo_rehearsal.py   # 跑完项目就是"走完了"，回到起点再跑一次 demo_reset
```

开演时打开链接：中间是项目，右侧是 Fitwise Agent。三页空态都写清了"把材料交给右侧 Agent"。

## 1. 材料解析（约 1 分钟）

| 你做什么 | 屏幕上会看到什么 |
| --- | --- |
| 把 `demo/` 下的**招标需求书**拖到页面任意位置（或在「客户材料」页点「选择文件上传」） | 整页出现虚线投放层；松手后对话里出现一张**材料卡**：「已收到 · 排队中」 |
| 等十几秒 | 材料卡变成「3 页 · 已读完」，并给出「查看原文」（要点数与需求候选数在悬停提示里） |
| 再把**答疑与补充通知**拖进去 | 第二张材料卡；两份读完后面板结论从"还不了解这个项目"变成"需求还没确认，判断先不下" |
| 切到中间「客户材料」页 | 材料清单（份数 / 页数 / 一句话摘要）+ 项目要点按 7 类分组 |

要讲的话：**材料是拖进对话的，读出来的东西落在中间页**；要点里"工期口径"会出现两条（4 个月 / 3 个月），这就是两份材料口径不一致被 AI 抓到。

## 2. 需求确认（约 1 分钟，全场重点）

| 你做什么 | 屏幕上会看到什么 |
| --- | --- |
| 对 Agent 说「帮我确认这些需求」 | 出现一张**待批准卡**：「把 N 条 AI 推断的需求设为基线（其中高优先级 M 条）；确认之后我会自动开始能力判断」 |
| 指着卡说「这一步必须人点」 | 卡上两个按钮：`批准并执行` / `先不做` |
| 点「批准并执行」 | 卡片变成「**已批准 · 张岚（售前）**」，紧接着自动跑起能力判断 |

要讲的话：**AI 只准备，不替人做决定**；批准由服务端留痕（谁、什么时候）；草稿需求可以逐条改，人工确认后才算客户诉求 —— 未确认的需求不会进入能力判断。

## 3. 能力判断（约 1 分钟）

| 你做什么 | 屏幕上会看到什么 |
| --- | --- |
| 等判断跑完（显示"正在判断 i/N"） | 每条需求给一个结论：完全支持 / 部分支持 / 暂不支持 / 待补依据 |
| 展开任意一条 | 「为什么这样判断？」+ 相关产品能力 + 判断依据（可点回原文页码）+ **取证过程**（检索 → 判断 → 自检 → 降级决策） |

预期会出现四类结论（实测分布：完全支持 2 · 部分支持 9 · 暂不支持 2 · 待补依据 1）：

- **完全支持**：馆内内网私有化全离线部署、信创适配（麒麟 V10 + 鲲鹏 920 + 达梦，有同类案例）；
- **部分支持**：准确率 99%、日均 8 万页、无边框台账、手写批注、多页 OFD、繁体褪色档案 —— 都有限制条件或需确认项；
- **暂不支持**：**5 类特殊档案**与**日均/峰值处理规模**这两条 —— 知识库里"大幅面工程图纸（A0/A1）不在标准解析范围"是 gap 信号，
  规则层直接把结论封顶；讲的时候说"这一类我们做不了，只能人工分幅或单独立项"；
- **待补依据**：档案数据不得留存或用于训练 —— 企业证据里没有这条，材料也没给，就不下结论。

要讲的话：结论不是模型拍的 —— 规则层先按企业内部资料给出**结论上限**，模型只能在允许范围内组织语言；每条判断都有自检，页码定位不上、没有支持信号、支持与缺口冲突都会自动降级。

> 顺带一句好讲的："连我们产品文档里写的『待验证』它都会捡出来" —— 信创那两条之所以能判完全支持，
> 是因为知识库里有对应案例；而达梦组合若没有验证记录，规则层会老老实实降成"部分支持"。

## 4. 售前建议（约半分钟）

| 你做什么 | 屏幕上会看到什么 |
| --- | --- |
| 对 Agent 说「生成售前建议」 | 动作卡跑完给出结论；状态卡上的「下一步」自动消失 |
| 切到中间的「售前建议」页 | 结论、风险、对客户 / 内部 / 销售的下一步、不可承诺清单 |

要讲的话：建议里的每条风险都能回指到具体判断与证据；正式承诺仍需人工确认。

## 5. 随手补两个问答（各 5 秒）

- 问「工期是多久」→ 带页码回答，点引用能回到原文那一页；
- 问「数据能不能用公有云」→ 会答"材料里没有提到"（或指出答疑里明确禁止公有云），没有证据就不给引用。

## 时间预算（实测）

| 环节 | 耗时 |
| --- | --- |
| 一份 3 页招标需求书解析（TextIn） | 10–30 秒 |
| 自动整理需求（DeepSeek） | 15–40 秒 |
| 能力判断 | 每条约 5–8 秒（10 条约 1 分钟） |
| 生成售前建议 | 20–40 秒 |

两份材料 + 完整链路通常在 4 分钟以内跑完。
